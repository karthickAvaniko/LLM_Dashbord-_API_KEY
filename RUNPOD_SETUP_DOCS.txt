Build a Gemini/Claude-style AI API platform on RunPod where:
- Admin can create and manage API keys
- Users call the API using their key (like Gemini API)
- Model: Qwen3-VL-32B-FP8 (vision + text + thinking mode)
- Use case: Invoice OCR, Chat, Coding

4. vLLM SERVER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

vLLM Version : 0.19.0
Port         : 8000
Command:

  python -m vllm.entrypoints.openai.api_server \
    --model /workspace/Qwen3-VL-32B-FP8 \
    --quantization fp8 \
    --dtype bfloat16 \
    --max-model-len 8192 \
    --gpu-memory-utilization 0.90 \
    --max-num-seqs 4 \
    --port 8000 \
    --host 0.0.0.0 \
    --trust-remote-code

Parameters:
  --max-model-len 8192     : Context window (8K tokens)
  --gpu-memory-utilization : 90% of 48GB = 43.2GB
  --max-num-seqs 4         : Max 4 concurrent requests
  --quantization fp8       : FP8 inference

Test command (verified working):
  curl -X POST http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{"model":"/workspace/Qwen3-VL-32B-FP8","messages":[{"role":"user","content":"Hello"}]}'

Response confirmed: "Hello! Yes, I'm working and ready to help you."

API Endpoints:
  GET  /dashboard                  → Serves dashboard HTML
  GET  /health                     → Health check (no auth)
  GET  /                           → Endpoint list

  POST /admin/keys/create          → Create API key (admin only)
  GET  /admin/keys/list            → List all keys (admin only)
  DELETE /admin/keys/{id}          → Revoke key (admin only)
  GET  /admin/usage                → View usage logs (admin only)

  POST /v1/chat/completions        → Chat with model (requires API key)
  POST /v1/vision/analyze          → Image OCR/analysis (requires API key)

Authentication:
  All /v1/* endpoints require header: x-api-key: ak_xxxxx
  All /admin/* endpoints require query param: admin_secret=xxxxx

Database tables:
  api_keys    : id, key, name, created_at, is_active, rate_limit
  usage_logs  : id, api_key, endpoint, prompt_tokens, completion_tokens,
                timestamp, status

7. HOW TO USE — API CALLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: Create API Key (Admin)
  curl -X POST https://<pod>-1111.proxy.runpod.net/admin/keys/create \
    -H "Content-Type: application/json" \
    -d '{"name":"user1","admin_secret":"admin_secret_change_this","rate_limit":100}'
  Response: {"api_key": "ak_xxxxx", "name": "user1"}

Step 2: Chat API
  curl -X POST https://<pod>-1111.proxy.runpod.net/v1/chat/completions \
    -H "x-api-key: ak_xxxxx" \
    -H "Content-Type: application/json" \
    -d '{"messages":[{"role":"user","content":"Hello!"}],"max_tokens":500}'

Step 3: Vision / Invoice OCR
  curl -X POST https://<pod>-1111.proxy.runpod.net/v1/vision/analyze \
    -H "x-api-key: ak_xxxxx" \
    -F "file=@invoice.jpg" \
    -F 'prompt=Extract invoice data as JSON'

Step 4: Python Example
  import requests
  API_KEY = "ak_xxxxx"
  BASE = "https://<pod>-1111.proxy.runpod.net"

  # Chat
  r = requests.post(f"{BASE}/v1/chat/completions",
      headers={"x-api-key": API_KEY},
      json={"messages": [{"role":"user","content":"Hello!"}]})
  print(r.json()["choices"][0]["message"]["content"])

  # Invoice OCR with thinking
  with open("invoice.jpg","rb") as f:
      r = requests.post(f"{BASE}/v1/vision/analyze",
          headers={"x-api-key": API_KEY},
          files={"file": f},
          data={"prompt":"Extract all fields as JSON","enable_thinking":"true"})
  print(r.json()["result"])

9. ISSUES FACED & SOLUTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Issue 1: Disk quota exceeded during model download
  Cause  : HuggingFace xet protocol writes temp files to container disk (/)
  Fix    : Used HF_HUB_DISABLE_XET=1 + hf_hub_download() one file at a time
           This writes directly to /workspace without temp files

Issue 2: Encrypted volume 80GB had ~20GB actual quota
  Cause  : RunPod encrypted volumes have hidden quota limits
  Fix    : Created new unencrypted Network Volume (100GB)
           Network volumes do NOT get deleted on pod terminate

Issue 3: Pod GPU became unavailable
  Cause  : A40 GPU taken by another user while pod was stopped
  Fix    : Used "Automatically migrate Pod data" option — data preserved

Issue 4: vLLM port 8001 already in use
  Cause  : Another process was using port 8001
  Fix    : Changed to port 8000

Issue 5: gateway.py /dashboard route returned 404
  Cause  : Code was appended after uvicorn.run() — never executed
  Fix    : Rewrote complete gateway.py with correct route order
